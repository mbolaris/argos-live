# Argos Live image updates and physical acceptance checklist

Prepared October 2, 2026 on Yugo, using SSH evidence from Toronado. Public source baseline: 2770c780fc4f8b8773350de4293535747047eac2. Toronado's Windows workspace and the local agent's UEFI-menu edits have not been reconciled with this clone. This is an implementation backlog, not a newly built or written image.

## Verified on physical Toronado

- XFCE desktop, LightDM and Xorg run when the desktop entry includes `console=tty0 module_blacklist=nouveau`.
- NVIDIA 550.163.01 loads for kernel 6.12.107+deb13-amd64 on the RTX 3090. Without the blacklist, the kernel reports that nouveau already owns the GPU and NVIDIA cannot probe it.
- Qwen3 seed blob SHA256 checks passed. Ollama generated a response using CUDA and offloaded 29/29 model layers to the GPU.
- Owner-passphrase LUKS2 persistence is the live root overlay's writable backing. Boot snapshots from multiple physical boots remain available.
- LAN SSH key login, pinned host key, restricted diagnostic export, and periodic collection work. OpenClaw and Ollama test listeners are loopback-only.
- Real `argos setup` and `argos start` succeeded in a disposable profile. OpenClaw gateway conversation and within-session recall passed against local Ollama; dashboard HTML was served with HTTP 200. Invalid gateway token was rejected. Authenticated requests for denied exec/read tools returned HTTP 404 (tool unavailable). Session storage and recall of the code survived a gateway restart; this was a process restart, not a physical reboot.
- The conversation configuration audit reported zero critical findings, one conditional reverse-proxy warning, and two informational findings. This configuration audit does not replace npm dependency auditing.

## P0 — before the next physical-image candidate

- [ ] **Make the working NVIDIA desktop boot permanent.** Keep `console=tty0`, remove `console=ttyS0,115200`, and include `module_blacklist=nouveau` in the NVIDIA desktop entry. Inspect the actual generated UEFI and legacy BIOS menus and initramfs. `/etc/modprobe.d/nvidia-blacklists-nouveau.conf` already exists in this running root, but nouveau still loaded on the failing boot; check whether the initramfs contains the policy. Keep a clearly labeled text diagnostic option. Files: `scripts/build.sh`, `scripts/enable-build-console.sh`, `scripts/repack-image.sh`, bootloader templates/hooks. Acceptance: two desktop boots without GRUB editing, XFCE active, nouveau absent, nvidia-smi working, and successful GPU generation.
- [ ] **Fix the desktop launcher dependency.** `argos.desktop` calls `xfce4-terminal --command=argos-launch`, but `xfce4-terminal` is absent. `xterm` and `x-terminal-emulator` are installed. Either explicitly add xfce4-terminal or use a compatible terminal invocation. Acceptance: click Applications → Argos Setup and Assistant as the live user; first setup and subsequent start work with visible errors and no manual shell command.
- [ ] **Integrate diagnostics into the shipped image.** Include the collector, persistent-journal settings, timer, mokutil and SSH packages. Make collection independent of graphical.target. SSH must remain opt-in until owner public key, account and trusted controller restrictions exist; generate host keys on the target, never ship private host/user keys. The locally installed bundle is not proof that a future clean image includes it. Acceptance: clean diagnostic boot provides logs over SSH and retains previous-boot evidence after restart.
- [ ] **Reconcile source and device identity before changing the USB.** Merge reviewed UEFI-menu repairs and Yugo's patch with Toronado's uncommitted workspace changes. Linux currently reports DataTraveler serial `08606E694934BF418705FC70`; the earlier Windows record used `0B8F640168E7`. Establish the mapping using live device properties and current partition/LUKS identities. Never target by historic disk number. Back up encrypted persistence before any proposed destructive update; obtain approval for new erasure. Acceptance: documented physical-device match and a reviewed preservation/restore plan before any write.
- [ ] **Recheck recorded dependency release blockers.** The repository's prior audit records brace-expansion, undici and ip-address advisories. Run a fresh audit against the exact deployed lockfile; evaluate patched upstream versions and rerun local-model compatibility before changing pins. Do not infer that the OpenClaw configuration audit clears npm advisories. Acceptance: reviewed dependency findings, reproducible package integrity and retained license inventory.

## P1 — startup, reliability and evidence

- [ ] **Supervise the whole assistant process tree.** Closing or terminating `argos start` must stop Ollama, OpenClaw wrappers/gateway, and model runners, without killing unrelated services. In the first controlled test, the parent/Ollama stopped but an owned OpenClaw gateway child remained orphaned; it exceeded the short cleanup wait and needed explicit termination. Its log advertises a shutdown budget of roughly 325 seconds. Review SIGINT/SIGTERM handling, timeouts and failed-start cleanup. Acceptance: graceful stop and forced-error tests leave no test listeners/processes; restart does not fail on occupied ports.
- [ ] **Wait for actual readiness and open the conversation UI.** Gateway health can initially succeed with `status=starting`. The current launcher starts the gateway but does not itself open a browser. Add clear startup progress and an authenticated local dashboard/open-chat action after readiness. Keep tokens out of logs and shared URLs. Acceptance: the owner can launch and converse from XFCE without CLI instructions; startup failures have useful diagnostics.
- [ ] **Improve collection accuracy.** Record snapshot time and boot ID beside every copied Xorg/LightDM log so stale persisted logs are not attributed to the current boot. Capture `modinfo nvidia-current` as well as Debian's nvidia alias, module signature/vermagic, kernel binding, and journal boot inventory. `modinfo nvidia` alone incorrectly says module not found on this installation even though nvidia-current is present. Acceptance: a known healthy GPU boot is reported accurately.
- [ ] **Make export atomic and bounded.** Serialize export with collection and exclude incomplete `.tmp` files; a first archive contained an in-progress snapshot. Bound copied display logs and journal output, identify command timeout/exit status, preserve recent boot ordering, and handle low persistence space. Acceptance: repeated concurrent timer/export requests produce complete, readable archives without racing or filling the USB.
- [ ] **Handle address changes deliberately.** Current SSH setup is restricted to Yugo 192.168.1.31 and Toronado 192.168.1.30. Add a visible way to update trusted-controller/listen addresses after reviewed DHCP changes, while keeping key-only login and forwarding disabled. Acceptance: reboot and reconnection work; unauthorized source addresses and password logins fail; no router forwarding.
- [ ] **Document Secure Boot support.** `mokutil` reports Secure Boot disabled in the successful physical boots. Do not describe this as verified Secure Boot compatibility. Review signed-module/certificate enrollment or a clearly documented owner-controlled alternative; never clear keys, change firmware or assume Windows BitLocker suspension. Acceptance: separately recorded firmware/security state and an explicit tested support policy.

- [ ] **Improve the bundled model's conversation experience.** Qwen3 0.6B recalled the test code, but added unwanted formatting; one turn required OpenClaw's automatic visible-answer retry after an empty response. A repeated test produced JSON resembling a tool_call/no-reply invocation instead of natural text. OpenClaw explicitly treated it as text; no actual tool executed. This is a release-quality issue despite successful inference and gateway transport. Evaluate a concise local prompt, thinking settings, empty-output handling and an optional larger model with an explicit download-size/free-space review. Acceptance: repeated greeting, recall, stop/cancel and simple-question tests with understandable answers. No unrequested model download.

## P2 — assistant quality and acceptance

- [ ] **Keep context budgeting compatible.** OpenClaw's physical test prompt was about 6.8k tokens. Preserve the 32768 context configuration or reduce the prompt deliberately; the direct GPU smoke's 2048 context is insufficient evidence for OpenClaw. Full-context Qwen3 used about 4.0 GiB of VRAM in the OpenClaw test. Acceptance: full gateway conversation works without context overflow; model/context memory tradeoffs are visible when they affect the user's choice.
- [ ] **Audit the effective tool surface after each runtime update.** The prompt exposes compact tool_search/tool_describe/tool_call wrappers; the log catalog reported two backing tools, while config denies runtime/filesystem/web/browser and elevation. Test actual denied shell/file calls rather than relying on the model to refuse. Preserve loopback token authentication. Acceptance: forbidden calls fail at the policy layer and benign conversation still works.
- [ ] **Complete owner-profile UI acceptance.** Disposable SSH-profile checks do not prove the desktop user's personal setup or browser WebSocket conversation path. After launcher repair, verify first-run setup, dashboard connection, two-turn conversation and transcript reopening under the live desktop user. Preserve existing private state and tokens.
- [ ] **Test physical assistant persistence and fully disconnected operation.** With owner coordination, start a test conversation in persistent storage, restart Toronado, unlock persistence and resume it. Then test with WAN unavailable. The current physical tests used local providers and no provider account, but Toronado remained network-connected for SSH; they do not prove network isolation. Acceptance: saved transcript/settings/model remain; conversation works without internet; SSH recovers when LAN returns.
- [ ] **Add a reproducible hardware acceptance runner and refresh status docs.** Capture kernel/driver/model/runtime versions, hashes, boot params, binding, health/readiness, auth denials, session recall, GPU offload, and cleanup status. Keep boot success, GPU generation, CLI/gateway conversation, GUI use, persistence and offline acceptance as separate checks. Update README/STATUS statements that still call physical GPU testing pending.
- [ ] **Perform a clean rebuild and nondestructive validation.** Verify generated menus, initramfs policy, package manifests, launcher dependencies and runtime smoke on fresh media/image. Existing in-place repairs and build/repack recovery are not reproducible-build proof. No physical rewrite until the approved target and persistence plan are re-established.

## Remaining scope limits

Desktop and GPU functionality are physically demonstrated. Firmware/Windows security settings were observed only where reported by running Linux; this session did not alter them. The existing encrypted persistence passphrase, internal disks, Windows boot files, TPM and firmware keys were not changed. Root SSH privileges remain limited to the boot-export command. The temporary OpenClaw test changed only its own disposable profile.

Reference behavior for the runtime test follows the official [OpenClaw Ollama provider](https://docs.openclaw.ai/providers/ollama), [agent CLI](https://docs.openclaw.ai/cli/agent), and [tool invocation API](https://docs.openclaw.ai/gateway/tools-invoke-http-api) documentation; physical test transcripts are the evidence for the installed versions.
